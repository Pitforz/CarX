## 2. Скачать проект

Откройте **Командную строку** (Win+R → `cmd` → Enter) и выполните по очереди:

```
git lfs install
cd /d C:\Dev
git clone https://github.com/Pitforz/CarX.git
```

Папку `C:\Dev` можно взять любую, но **без русских букв и пробелов в пути**.
Картинки, модели и звуки лежат в Git LFS и скачиваются вместе с проектом. Если потом в Unity текстуры розовые или пустые, выполните в папке проекта `git lfs pull`.

Вместо командной строки можно использовать **GitHub Desktop** (File → Clone repository → URL → `https://github.com/Pitforz/CarX.git`).

## 3. Открыть проект в Unity

1. Unity Hub → **Projects** → **Add** → **Add project from disk** → выберите папку `CarX` (ту, где лежат `Assets`, `Packages`, `ProjectSettings`).
2. Проект появится в списке, рядом будет версия **6000.6.9f1**. Нажмите на него.
3. Первое открытие идёт долго: **5–20 минут**. Unity скачивает пакеты и строит папку `Library`. Это нормально, ничего не трогайте.
4. Если появилось окно **Enter Safe Mode?** — значит, в коде ошибка компиляции. Нажмите **Ignore**, откройте **Window → General → Console** и пришлите красные строки программисту.
5. Если появилось окно **Administrator Privileges Detected** — нажмите **Restart as Standard User**. Unity не нужно запускать от имени администратора.

## 4. Пакеты Unity и общие архивы с ассетами

Пакеты из `Packages/manifest.json` ставятся **автоматически** при первом открытии:

- **Universal Render Pipeline (URP)** — графика;
- **Input System** — управление;
- **Cinemachine** — камера игрока;
- **ProBuilder** — моделирование уровней прямо в Unity;
- **AI Navigation** — навигация NPC;
- **Splines**;
- **Yarn Spinner** — диалоги (качается с GitHub, поэтому нужен установленный Git);
- **Unity AI Assistant** — необязательный помощник внутри редактора, может просить вход в аккаунт, можно игнорировать.

Ассеты, которые уже лежат в репозитории и ничего не требуют:

- `Assets/Starter Assets` — контроллер игрока от первого лица (Unity Starter Assets);
- `Assets/_Project` — всё наше: сцены, скрипты, шейдеры, материалы, сгенерированные текстуры.

**Не входит в репозиторий:** персонажи и анимации **Mixamo** (`Assets/ThirdParty/Mixamo`, около 570 МБ). Бесплатный GitHub LFS даёт только 1 ГБ места и 1 ГБ скачиваний в месяц, поэтому эту папку передаём архивом отдельно (спросите у Фёдора). Без неё не работает только сцена `NPC_Demo`: NPC будут без моделей. Архив распакуйте так, чтобы получилось `Assets/ThirdParty/Mixamo/Characters` и `Assets/ThirdParty/Mixamo/Animations`.

**Ошибки `Missing Prefab` для мусора и деревьев.** Возьмите командный архив `CarX_Packs_Trees_Trash.zip` с общего Диска. Закройте Unity и перенесите из архива папки вместе с исходными `.meta` в `Assets/URP_WasteOvergrowth_SA/` и `Assets/TreePackVol.1/`. Рядом с папками положите их одноимённые `.meta`, если они есть в архиве. После импорта Unity восстановит ссылки по исходным GUID. Эти папки перечислены в `.gitignore` и передаются архивом.

## 5. Окна Unity за минуту

- **Hierarchy** (слева) — список объектов открытой сцены.
- **Scene** (центр) — редактор уровня. Крутить камеру: зажать **правую кнопку мыши** и двигать мышь, летать — **ПКМ + WASD**. Приблизиться к выбранному объекту — клавиша **F**.
- **Game** — то, что видит игрок.
- **Inspector** (справа) — настройки выбранного объекта.
- **Project** (снизу) — файлы проекта.
- **Console** (снизу, вкладка рядом с Project) — ошибки и сообщения.

Если какое-то окно пропало: **Window → Layouts → Default**.

## 6. Как запустить уровень

1. Внизу в **Project** откройте папку **Assets → _Project → Scenes**.
2. Дважды кликните по сцене (список ниже).
3. Нажмите **▶ Play** вверху по центру. Кликните мышкой в окно **Game**, чтобы оно поймало мышь и клавиатуру.
4. Выйти из игры — снова нажать **▶** (или **Ctrl+P**). Отпустить мышь во время игры — **Esc**.

> ⚠️ Всё, что вы меняете в сцене **во время Play**, после остановки пропадает. Кнопка Play подсвечена синим — значит, вы в игре.

**Управление:** WASD — ходьба, мышь — взгляд, Shift — бег, Space — прыжок, **F — фонарик** (в TunnelMaze_Demo).

| Сцена | Что это |
|---|---|
| **TunnelMaze_Demo** | Случайный лабиринт ливнёвок: 25 камер-развязок, тоннели разного сечения, лужи, подъёмы наверх (ливнёвки с решёткой, люки с лестницей) с дневным светом. Фонарик на F. Главная демонстрация тоннелей. |
| **TunnelGraph_Demo** | Тот же лабиринт, но построенный **графом тоннелей** (см. п. 7): 25 камер, тоннели разных типов, длинный плавный тоннель на восток с поворотами и спуском. Выделите объект TunnelNetwork, чтобы править граф. |
| **TunnelKit_Demo** | Ранний вариант: тоннель из готовых модулей-префабов (прямые, повороты, T, X). |
| **NPC_Demo** | Бездомные NPC с анимациями Mixamo (нужна папка Mixamo, см. п. 4). |
| **Sandbox** | Песочница Фёдора. Не редактируйте без спроса. |
| `Assets/Scenes/SampleScene` | Пустой шаблон Unity, не используется. |

**Целой игры пока нет**: сейчас это набор демо-сцен. Когда появятся уровни, их добавят в **File → Build Profiles → Scene List**, и игру можно будет собрать в .exe кнопкой **Build**.

## 7. Инструменты тоннелей (для тех, кто строит уровни)

### Граф тоннелей (основной способ)

Уровень рисуется как схема из линий, тоннели и камеры строятся по ней сами.

1. **CarX → Tunnels → New Tunnel Network (граф)** — создать граф (или откройте сцену TunnelGraph_Demo).
2. В окне Scene появится панель «Граф тоннелей» (её можно перетащить за заголовок). Кнопка **«Сверху»** — вид сверху, **«Схема»** — спрятать тоннели и видеть только линии.
3. Инструменты (по умолчанию «Выбор»; тоннели перестраиваются, когда отпускаете мышь):
   - **Перо** — клик ставит узел и тянет линию от предыдущего. Клик по узлу соединяет с ним, **Shift+клик по линии** делает врезку в неё. Esc заканчивает линию. Правая и средняя кнопки мыши, как обычно, крутят камеру.
   - **Выбор** — клик по узлу или линии. Узел двигается стрелками (в том числе вверх-вниз), Delete удаляет. Настройки узла и линии в инспекторе.
   - **Кисть** — перекрасить линию в выбранный тип тоннеля (с Shift весь тоннель).
   - **Метка** — поставить на линию ливнёвку, решётку или люк.
   - **Ножницы** — по линии: вставить узел; по узлу: убрать его.
4. Цвет линии = тип тоннеля. Типы лежат в `Assets/_Project/Tunnels/Types`: сечение, длина плиты, **максимальный угол между плитами** (сейчас 2°).
5. Углы скругляются сами с минимальным радиусом для типа (2° и плита 2 м дают радиус около 57 м). Там, где сходятся 3 и больше линий, тоннели врезаются друг в друга напрямую: самый широкий идёт насквозь, остальные входят в его стену (врезку ставьте на прямой участок). Если в узле встречаются два разных типа торец в торец (например, восьмиугольник и труба), камеры нет: больший тоннель кончается стенкой с проёмом, меньший идёт дальше из неё. Высоту меньшего над полом задаёт **Join Lift** у узла (по умолчанию пол к полу). Меньший тоннель входит в стену большего без своего торца и выступов: проём обрамляет только больший тоннель, а если меньший выше, над проёмом остаётся стенка-перемычка. Камера-развязка ставится сама только если сечения почти не перекрываются, линия разворачивается назад или угол слишком крутой; в любом узле её можно включить кнопкой «Сделать камерой-развязкой» (инструмент «Выбор», инспектор графа).
6. Если что-то не помещается, в инспекторе графа появится список **«Проблемы»** с кнопкой «Показать».
7. **Свои типы:** в панели «+ Новый тип» копирует выбранный тип, «Настроить тип» открывает его настройки (высота, ширина, длина плиты, угол, **Seamless** = без швов между плитами). Тоннели пересобираются сразу.
8. **Крутые углы:** если дуга не помещается, угол одного типа строится коленом (срез под углом), до 100°. Если на крутом углу меняется тип, меньший тоннель выходит из боковой стены у конца большего.
9. **Комнаты:** выберите узел → «Сделать комнатой». Углы двигаются жёлтыми точками, зелёная точка на стене добавляет угол, Shift+клик по углу убирает. Высота потолка по умолчанию = самый высокий тоннель (поле Room Height). Тоннели входят у пола, можно под углом до 60° к стене. Если стена уже проёма, угол комнаты срезается новой стеной поперёк тоннеля (в схеме она видна оранжевой линией). Кнопки «+ Колонна квадратная/круглая», колонны двигаются голубыми точками. Отдельная колонна: компонент **CarX/Concrete Column**.
10. **Модели для художников:** CarX → Tunnels → **Export Prototype Models (OBJ)** пишет в `Assets/_Project/Tunnels/Prototypes` прямой участок, 3 плиты, колена 45° и 90°, тупик для каждого типа, плюс колонны и пример комнаты.
11. **Пропсы, NPC, граффити (якоря):** кладите объекты в папку **Props** внутри графа (кнопка «Создать папку Props» в инспекторе графа). Каждый объект там сам получает компонент **Tunnel Anchor** и привязывается к ближайшему тоннелю, камере или комнате и к поверхности: пол, стена, потолок или «в воздухе». Двигаете узлы или меняете тип тоннеля: объект сохраняет расстояние от ближайшего неподвижного узла, остаётся на своей поверхности и так же повёрнут относительно неё. Двигаете сам объект: он просто привязывается заново. Объект вне папки: правый клик → **CarX → Привязать к тоннелю**. Если рядом нет тоннеля (дальше 1,5 м от стен), объект стоит на месте и считается «без тоннеля», в инспекторе графа есть кнопка «Выделить объекты без тоннеля». **Граффити** = GameObject → Rendering → **URP Decal Projector** в папке Props, направленный в стену (Renderer Feature «Decal» уже включён в `Assets/Settings/PC_Renderer` и `Mobile_Renderer`).

Объекты внутри `TunnelNetwork/_Generated` руками не правьте: они пересобираются из графа.

### Тоннели по точкам (старый способ)

Меню **CarX → Tunnels**:

- **New Tunnel Path** — новый тоннель. Он строится по точкам `Point_0, Point_1…` (дочерние объекты). Двигайте точки стрелками в окне Scene, тоннель перестраивается сам.
- **New Junction Chamber** — бетонная камера-развязка. Перетащите тоннели в поля North/East/South/West и нажмите **«Пристыковать тоннели»**: проём в стене вырежется по форме тоннеля.
- **Build Random Maze Demo** — заново собрать случайный лабиринт (перезаписывает сцену TunnelMaze_Demo).
- **Build Graph Maze Demo (граф)** — собрать лабиринт графом (перезаписывает сцену TunnelGraph_Demo).
- **Remove Sand Piles (open scenes)** — убрать старые кучки песка из открытых сцен.
- **Add Atmosphere** — темнота, туман и пост-эффекты для открытой сцены.
- **Regenerate Textures and Materials** — пересоздать процедурные текстуры бетона, грязи, песка и т. д.

В инспекторе тоннеля (выделите объект с компонентом **Tunnel Path**):
- сечение: восьмиугольник, короб с бордюрами, квадрат, прямоугольник, круглая труба;
- кнопки **+ Ливнёвка / + Решётка / + Люк** — подъём наверх; двигать его вдоль тоннеля жёлтым шариком в окне Scene;
- **Раскидать лужи** / **Убрать лужи**;
- все числа (длина плит, щели, полоса грязи и т. д.) меняются на лету.

Подсказка: в окне Scene есть кнопка освещения (лампочка в верхней панели). Если в редакторе всё чёрное — это нормально, тоннели тёмные; включите/выключите освещение сцены этой кнопкой.

## 8. Как работать вместе

1. **Перед началом работы** получите свежую версию: `git pull` (или Fetch/Pull в GitHub Desktop). Unity при этом лучше закрыть.
2. Сохраняйте сцену: **Ctrl+S**.
3. Отправить изменения (Unity сохранить, можно не закрывать):
   ```
   cd /d C:\Dev\CarX
   git add -A
   git commit -m "Коротко, что сделано"
   git push
   ```
4. Правила:
   - **одну сцену одновременно правит один человек**, остальное — через префабы (сцены плохо сливаются);
   - файлы `.meta` всегда коммитятся вместе с файлом — не удаляйте их;
   - не коммитим `Library/`, `Temp/`, `Logs/`, `UserSettings/` (уже в `.gitignore`);
   - сторонние ассеты кладём в `Assets/ThirdParty/`, свои — в `Assets/_Project/`;
   - большие файлы (больше ~50 МБ) сначала обсудите: место в LFS ограничено.

## 9. Тяжёлые файлы (важно!)

**Лимит.** Бесплатный GitHub даёт на весь репозиторий 1 ГБ хранилища под картинки, модели и звук (Git LFS) и 1 ГБ скачиваний в месяц на всех. Сейчас занято ~145 МБ, и каждое новое скачивание проекта тратит ещё ~145 МБ трафика. Старые версии файлов из истории не исчезают, поэтому каждая перезаливка большой модели съедает место заново.

**Что спокойно идёт в Git.** Код, сцены, префабы, материалы, текстуры до ~10 МБ, звуки до ~10 МБ и все `.meta`-файлы. Картинки, FBX, звук и видео сами уходят в LFS (настроено в `.gitattributes`), ничего делать не нужно. Достаточно один раз выполнить `git lfs install`.

**Что НЕ кладём в Git:** файлы больше ~50 МБ и паки больше ~100 МБ. Порядок такой:
1. Кладём в `Assets/ThirdParty/<Название>/`.
2. Добавляем эту папку (и её `.meta`) в `.gitignore`.
3. Запаковываем в zip **вместе с .meta-файлами** (без них ломаются ссылки в префабах) и заливаем в общую папку на Google Диске.
4. Пишем в чат, что появилось и куда распаковывать.

**Сначала уменьшить, потом добавлять.**
- Анимации Mixamo качать с опцией **Without Skin**: это 1–3 МБ вместо 50 МБ. Персонажа With Skin нужно скачать только один раз.
- Текстуры не больше 2048×2048, формат PNG или JPG. PSD и TIFF в проект не кладём.
- Музыка в OGG или MP3, а не в WAV. Видео без крайней нужды не добавляем.

**Перед каждым пушем** посмотреть `git status`: не попало ли туда что-то огромное или лишнее. Один и тот же большой файл не перезаливать по десять раз.

**Ассеты из Asset Store:** импортировать в `Assets/ThirdParty/` и коммитить только то, что реально используется. Большие паки каждый ставит сам через Window → Package Manager → My Assets, той же версии.

**Если при `git clone` или `git pull` появилась ошибка LFS** (smudge / quota exceeded), значит кончился месячный трафик. Берём архив проекта с Диска и пишем Фёдору.

**Что сейчас лежит на Диске, а не в Git:** `CarX_Mixamo.zip` (~565 МБ, персонажи и анимации Mixamo вместе с .meta). Распаковать в корень проекта (рядом с `Assets` и `Packages`), Unity должен быть закрыт.

## 10. Частые проблемы

| Симптом | Что делать |
|---|---|
| Hub пишет, что версия не установлена | Поставить 6000.6.9f1 (п. 1), не открывать в другой версии. |
| Всё розовое | Не скачались текстуры LFS → `git lfs pull` в папке проекта. Или открыто не той версией Unity. |
| Красные ошибки в Console после `git pull` | Подождать, пока Unity перекомпилирует (крутится значок справа внизу). Если не прошло — прислать текст ошибки программисту. |
| Ошибка про Yarn Spinner / git при открытии | Не установлен Git или Unity запущен до установки Git → поставить Git, перезапустить Unity Hub. |
| Персонаж не двигается | Кликнуть в окно Game. Проверить, что нажат Play. |
| Unity упал | Просто открыть заново; несохранённые изменения могут пропасть, поэтому чаще жмите Ctrl+S. |

- `Assets/_Project/Scripts/Editor/CarXRemoteBridge.cs` — служебный мост, через который Claude управляет редактором (читает команды из `Logs/carx_cmd.txt`). Никому не мешает, в игру не попадает.
- Объекты на графе: `TunnelAnchor` (Level) слушает событие `TunnelNetwork.LaidOut` и переставляет объект; запросы к раскладке: `EdgeFrame`, `EdgeSpan`, `ClosestOnTunnels`, `ChamberAt`, `RoomAt`. Тест: `CarX.EditorTools.TunnelGraphDemo.BuildTestScene` (сцена Scenes/Test/TunnelGraph_Test, итог в Console: flush/room doors/anchors).
- Unity 6.6: `Object.GetInstanceID()` устарел и даёт ошибку компиляции — используйте `GetEntityId()` или `GetHashCode()`.
