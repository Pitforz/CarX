# Режим ориентирования в темноте

Игрок выставляет руки вперёд, руки ищут, к чему прикоснуться, и держатся за точку касания, пока игрок не отойдёт. Вокруг точки касания поверх темноты рисуется карта глубины, остальная картинка размыта и притушена. Руки чёткие, с контуром.

## Управление

- **G**: включить или выключить режим. Включается только при выключенном фонарике.
- Включили фонарик (F): режим выключается.
- Пистолет в правой руке: ищет и касается только левая рука, пистолет остаётся чётким и обведённым.
- Пока открыт инвентарь или меню, G не работает.

## Как подключено

Ничего ставить не нужно. Модуль сам появляется в каждой сцене, где есть игрок (объект с тегом `Player` и `CharacterController`): создаётся объект `_CarX_DarkOrientation`. Общие сцены, префабы, материалы, настройки URP и слои не меняются.

- Выключить в конкретной сцене: добавить в неё компонент **CarX/Dark Orientation/Disable In This Scene**.
- Выключить везде: снять галочку `autoInstall` в настройках.
- Поставить вручную: компонент **CarX/Dark Orientation** на любой объект сцены.

## Настройки

`Runtime/Resources/CarX.DarkOrientation/DarkOrientationSettings.asset`: клавиша, радиус зоны (по умолчанию 15 см), мягкость края, цвета карты глубины, яркость и размытие остальной картинки, толщина контура, досягаемость рук и расстояние, на котором рука отпускает точку. Изменения во время Play сохраняются.

## Устройство

| Папка | Что там |
|---|---|
| `Runtime/Core` | `DarkOrientationController` (единственная точка входа), настройки, автоподключение |
| `Runtime/Hands` | `HandRig` (описание любой руки), процедурные руки, IK, поведение руки |
| `Runtime/Touch` | якорь касания, маркеры, триггеры для NPC |
| `Runtime/Rendering` | проход рендера: маска рук, размытие, сборка кадра |
| `Shaders` | три скрытых шейдера `Hidden/CarX/DarkOrientation/*` |
| `Integration` | `DarkOrientationPlayerBridge`: единственный файл, который знает про игрока (фонарик, пистолет, инвентарь) |
| `Editor` | инспектор `HandRig`, сборщик тестовой сцены (**CarX → Dark Orientation → Build Test Scene**) |
| `Tests` | тесты IK и процедурной руки (Window → General → Test Runner, EditMode) |

Сборка `CarX.DarkOrientation` не зависит от скриптов игрока: она получает только тело игрока и камеру, а правила (фонарик, пистолет, меню) приходят через `InputBlockedQuery`, `ForceOffQuery`, `HandOccupiedQuery` и `ExtraSilhouettes`. Если скрипты игрока поменяются, править нужно только `Integration/DarkOrientationPlayerBridge.cs`.

Эффект рисуется своим проходом URP, который ставится в очередь из кода только для камеры игрока и только пока режим виден. Renderer Feature добавлять не нужно.

## Свои руки вместо процедурных

1. Положить модель рук в сцену, на её объект добавить **CarX/Dark Orientation/Hand Rig** (по одному на руку, указать сторону).
2. Нажать «Из Humanoid» (для персонажей Mixamo и других Humanoid) или «По именам костей» (Generic-риги: Mixamo, Unreal, Rigify), затем «Проверить».
3. Передать риги в контроллер: поля `Left Rig` / `Right Rig` или в коде `DarkOrientationController.Current.SetHandRig(HandSide.Left, rig)`.

Оси суставов вычисляются из позы покоя, поэтому настраивать их под конкретную модель не нужно. Когда появятся анимации, IK модуля останется поправкой поверх них.

## Для разработчика NPC

У NPC сейчас нет коллайдеров. Пока режим включён, модуль сам вешает на кости Humanoid-персонажей рядом с игроком невидимые триггеры (слой Ignore Raycast, компонент `DarkTouchProxy`) и удаляет их при выключении. В сцены и префабы ничего не сохраняется, поэтому конфликтов при слиянии веток нет.

- Если у NPC есть свои обычные коллайдеры, модуль триггеры не создаёт, и руки касаются этих коллайдеров.
- Свой триггер, за который можно держаться: добавить на него компонент `DarkTouchProxy`.
- Объект, которого руки касаться не должны: компонент `DarkTouchIgnore`.
- Реакция на касание: события `DarkOrientationController.TouchBegan` / `TouchEnded` (в `TouchInfo.collider` будет коллайдер NPC или его триггер).
